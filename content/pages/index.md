# 声明协作，按约交付

Orchpact（序契）用可移植的工作流定义描述职责、依赖、交付规则和独立审校，由可自托管的持久化运行时推进执行。团队声明装配为每次独立的 Crew、Task 与 Agent，由 CrewAI 推进岗位协作和自主行动，工作流状态、授权、账务和验收由 Orchpact 维护。

一份定义可以被多个独立应用固定引用；各 Workspace 绑定自己的资源，每次执行保留自己的输入、付款人、调用、产物与验收记录。

## 从架构理解运行

Orchpact 维护业务阶段图、资源绑定、授权、调用回执与交付验收。CrewAI 在当前团队内装配并执行 Tasks/Agents，维护多轮行动和上下文交接。每次团队启动创建新的运行对象；长期共享的是声明，跨团队交接的是已登记产物。

先阅读[系统架构](/docs/architecture/)、[两者的职责边界](/docs/execution/)和[团队声明与实例](/docs/teams/)。首页的[执行事件示意](/#execution)可以逐步查看正常交付、返工与未知外部结果，不会调用模型。

## 先走通一条流程

1. [快速开始](/docs/quickstart/)：启动一个全新实例，发布示例工作流并安装。
2. [工作流、应用与安装](/docs/workflows/)：理解发布定义、固定应用引用、空间安装和执行的四个边界。
3. [API 与应用接入](/docs/applications/)：使用签名身份接入，并处理权限、幂等和修订冲突。

想先运行完整网页应用，可以从独立的 [examples 示例仓库](https://github.com/orchpact/examples)开始。观测、映序、拾页和诗境各有工作流与操作指南，统一脚本自动完成本机数据库、账号、资源安装和网关配置；不需要手工创建组织或复制密钥。

## 为什么把这些边界分开

定义表达可分享的规则；应用保留自己的接入身份；Workspace 决定本地资源；执行记录冻结当时的上下文。发布新的定义不自动移动应用引用，移动引用不自动升级空间，也不回写已有执行。

这使同一工作流可以交给不同的人、团队和应用使用，而无需在通用执行器中添加某个产品的专属分支。它不要求所有人交由同一个操作者调配。

完整定义字段、资源槽位、修订与安装冲突见[工作流协议](/docs/workflows/)；具体身份、签名与消费接口见[应用接入](/docs/applications/)。

## 了解运行边界

- 一个主进程、一份专用 PostgreSQL 数据库和配套文件目录；目前不提供多主分布式调度。
- 外部结果未知时保留预留并恢复真实回执，不自动重放付费请求。
- 生成的业务代码只作为产物交付，不自动执行、安装或部署。
- 业务流程由消费应用与工作流定义表达；外部 Agent 适配不在当前范围。

参见 [架构](/docs/architecture/)、[备份与恢复](/docs/postgresql/)和[公开接口](/docs/compatibility/)。
