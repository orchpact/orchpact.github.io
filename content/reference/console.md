# 管理台

入口 `/admin/`，原生 JavaScript、独立样式，无 npm 构建依赖。`static/kernel/` 提供工作台；`static/account/` 提供账号与积分界面。

管理台按“发布定义 → 应用固定引用 → Workspace 安装资源 → 查看执行与交付”管理工作流生命周期。它提供工作总览、空间切换、工作流目录、应用绑定、公钥、团队/岗位职责、项目工作项/产物/请求、问题回答、重试/取消、计划修改、授权/撤销、验收、治理规则和提供者配置。账号页提供邀请、空间成员、积分调整和待核定费用。

组织包、策略和提供者采用 JSON 编辑器，保存错误保留输入。文档与计划修改使用 revision，命令使用稳定幂等键。页面切换中止旧请求，编辑器绑定开始编辑时的 Workspace，避免空间切换后的误保存。名称、描述及模型文本均转义。

提供者编辑支持已有适配协议的连接与价格，密钥仅写入。管理凭据只用于登录，不保存在浏览器存储。下载文件按实际权限验证，支持明确指定 Workspace 的管理台链接。


## 待处理与费用状态

“待处理”只读汇总当前 Workspace 最近 100 个项目，展示问题、待独立验收的当前产物、停止后仍持有预留的调用、未知外部结果以及执行异常。每项显示原因、下一步行动和原项目链接；不是全历史收件箱，也没有负责人分派、通知或自动重试。已取消项目只保留回执与账务类事项。

运行中的调用和正常依赖等待不进入人工待办。账务状态与 Token 完整性分别显示：已结算但 Token 未知，不会重复要求核定；外部结果未知仍需查真实回执。待验收依据任务冻结策略，不随当前平台策略变化。页面不改变任何授权、验收或扣账规则。


## 工作流目录与应用绑定

管理导航分别提供“工作流目录”和“应用绑定”。目录负责登记、发布修订和导出明确版本；可从同一资产创建多个不同应用绑定。应用页负责固定版本调整、签名公钥和各空间模型安装预览。发布、应用改绑、空间升级均不自动串联。内联组织包仍显示在应用页，并提供定义编辑入口。

安装前只读预览当前目录来源、应用修订、已安装修订、模型与操作，确认后再提交。修改绑定会使旧预览失效，切换页面/空间会中止请求；服务端检查应用绑定与空间安装两类修订。编辑或导出定义不包含安装绑定，已有执行继续使用原快照。资源绑定采用 JSON 编辑，不提供图形流程设计器。

## 团队声明与执行对象

组织页显示团队岗位数量与职责；“编辑职责”的 crew JSON 可声明成员、顺序、模型和能力。它编辑的是可复用声明，不是当前 Crew 会话。工作流节点通过 participants 选择参与岗位，已受理工作的名单与模型保持快照。

每次实际启动创建新的 CrewAI Crew、Task 和 Agent。团队内部协作不会新增对应的业务工作项，不能将组织树、工作项树与 Agent 列表混为一组对象。运行查询中的 crew_runs 关联实际 Crew 与岗位名单，agent_steps 关联模型/工具步骤；其元数据遵循 run 的权限，工具参数与观察正文保存在实例私有文件中。字段见 [应用 API](APPLICATIONS.md)，执行规则见 [团队设计](TEAM_EXECUTION.md)。
