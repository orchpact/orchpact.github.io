01 / THE ARCHITECTURE

两层编排，
各自负责。

业务阶段由 Orchpact 推进。团队内部的任务协作、工具选择和多轮行动交给 CrewAI。边界落在调用链和数据模型中。

01
WORKFLOW LAYER

Orchpact

声明 / 治理 / 持久化
定义如何复用
不可覆盖的工作流修订、应用固定引用、Workspace 独立资源绑定。
阶段如何衔接
统一任务图、依赖领取、交付契约、独立审校与有界定向返工。
行动如何被接受
身份与能力检查、预算和积分预留、实际回执、结算及产物验收。
run / work item / attempt / artifact
02
TEAM EXECUTION LAYER

CrewAI

协作 / 行动 / 候选输出
装配本次团队
每次实际启动创建新的 Crew、Task 和参与岗位 Agent，运行对象不跨项目共享。
推进团队内部工作
按参与名单生成顺序 Tasks，通过 Task context 交接记录。
选择下一步行动
Agent 选择当前允许的工具，观察结果后继续，或返回契约要求的候选 JSON。

02 / THE PORTABLE CONTRACT

让工作流成为
可以分享的资产。

声明描述协作结构与资源能力。使用方绑定自己的模型、身份和空间。工作流修订、应用引用与空间安装分别推进。

  1. 01

    发布定义

    保存作者版本、目录 revision 与定义指纹。

    workflow_id + revision + SHA-256
  2. 02

    应用固定引用

    多个应用可引用同一修订，各自保留签名身份。

    application binding revision
  3. 03

    空间安装资源

    模型能力槽位映射为本实例模型，安装显式确认。

    Workspace + models bindings
  4. 04

    执行冻结快照

    保存当时的声明、岗位、模型、付款人与限制。

    run → work item → attempt

发布新定义不会自动移动应用引用，也不会改写已受理执行。

03 / FROM INTENT TO ACCEPTANCE

沿着一次执行，
看见每道边界。

受理、快照、团队行动与产物验收，是不同的状态变更。逐步查看正常交付、审校返工和外部结果未知时，系统分别保留什么。

04 / INVARIANTS, NOT INTENTIONS

把约束放进运行时。

提示词表达目标。身份、资金和交付状态由服务端规则维护。

01
ACTION SCOPE

每次行动重新授权。

模型支持搜索，不代表每个岗位都能搜索。当前角色能力、授权范围、期限、预算和停止标志在实际调用前复查。

role ∩ mandate ∩ limits
02
ACCEPTANCE IDENTITY

验收属于具体产物。

契约校验、专业审校与最终接受分开。验收绑定产物、哈希与执行代次；返工生成新产物并获得对应的新验收。

artifact + hash + generation
03
DURABLE EFFECTS

费用与恢复尊重回执。

先预留，按实际用量结算；未知用量保留未知。重启先恢复回执与结算，明确重试继续使用原付款人和生命周期边界。

reserve → receipt → settle

确定性规则检查已声明的结构与一致性。专业内容质量仍需独立评估；严格业务要求应进入可验证的契约。

05 / THE PERSISTENCE MODEL

单主进程。
持久事实在框架之外。

Orchpact 以可自托管服务运行。Python wheel 是安装载体，HTTP 与声明格式是集成边界；Agent 内存不承担恢复与账务真相。

当前实现边界

部署
单机、单主进程的模块化单体
团队
CrewAI sequential；岗位选择与顺序由声明确定
受控工具
search_evidence / read_artifact
默认 attempt 限制
12 次模型决策 · 8 次工具步骤
300 秒 · 128000 字符历史
持久化
PostgreSQL + 配套文件目录；同一数据库仅一个 owner

同一 attempt 内所有成员与辅助 Crew 共享额度。JSON 修正产生的实际请求分别计费。当前不提供远程 Worker、多主调度或任意生成代码执行。
